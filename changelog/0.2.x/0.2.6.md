# 0.2.6 — 2026-06-30

## Changed

- **`courtlistener_get_opinion` / `courtlistener_get_docket` court names** — `resolveCourtName` now resolves all 471 in-use CourtListener courts — district, bankruptcy, and state, not just the 14 federal appellate — from a generated `src/services/courtlistener/court-names-data.ts` snapshot of `/courts/?in_use=true`, with `full_name` values verbatim from the API. Resolution stays local (no per-request API call under the 5 req/min free-tier limit); ids absent from the snapshot still fall back to the raw `court_id`. [#27](https://github.com/cyanheads/courtlistener-mcp-server/issues/27)
- **`courtlistener_get_judge` `nomination_process`** — now expands the coded `how_selected` selection method to a readable label (e.g. `a_pres` → "Appointment (President)") via the existing `expandCode` pattern; unknown codes pass through unchanged. The `appointer` field description is corrected to state the value is a position URI (e.g. `.../positions/123/`), not a resolved name. [#28](https://github.com/cyanheads/courtlistener-mcp-server/issues/28)
- **`User-Agent` header** — `courtlistener-mcp-server/0.2.5` → `courtlistener-mcp-server/0.2.6`, synced to the package version.

## Fixed

- **`courtlistener_get_opinion` empty opinion text** — `html_text` now falls back across CourtListener's HTML/XML variant fields (`html_with_citations` → `html` → `html_columbia` → `html_lawbox` → `xml_harvard` → `html_anon_2020`) instead of reading only `html`. Sub-opinions whose text lives in a non-`html` field — most pre-2000 case law, e.g. Roe v. Wade (cluster 108713) — now return text where they previously returned empty strings. The `Opinion` interface gained the missing variant fields (`html_columbia`, `html_lawbox`, `xml_harvard`, `html_anon_2020`). [#21](https://github.com/cyanheads/courtlistener-mcp-server/issues/21)

## Security

- **`@cyanheads/mcp-ts-core` ^0.10.9 → ^0.10.10** — clears transitive advisories flagged by `bun audit`: `hono` (CORS wildcard reflected with credentials) → 4.12.27, `js-yaml` (quadratic-complexity DoS) → 3.15.0, and `vite` → 8.1.2. `bun audit` now reports no vulnerabilities.
