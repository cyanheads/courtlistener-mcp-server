# 0.2.5 — 2026-06-30

## Changed

- **`User-Agent` header** — `courtlistener-mcp-server/0.2.4` → `courtlistener-mcp-server/0.2.5`, synced to the package version.
- Dependencies: `@biomejs/biome` ^2.5.0 → ^2.5.1, `@types/node` ^26.0.0 → ^26.0.1.

## Fixed

- **`courtlistener_get_parties` output validation** — `total_parties` is now `z.number().nullable()`. `/parties/` serves `count` as a URL string (and `?count=on` drops the `results` array), so the service derives the total from the row count on a single page and reports `null` mid-pagination. `next_cursor` now returns the next page number — `/parties/` is page-paginated (`?page=N`), so the prior `cursor=` extraction never matched — re-enabling the "more parties — pass `page=N+1`" hint. [#22](https://github.com/cyanheads/courtlistener-mcp-server/issues/22)
- **`courtlistener_get_parties` party role** — a `toDocketId()` helper resolves `party_types[].docket` from its `.../dockets/<id>/` URL form (previously `Number(url)` → `NaN`, so the role match never fired and `role` was always `null`); roles now resolve to `Plaintiff`/`Defendant`/etc. [#29](https://github.com/cyanheads/courtlistener-mcp-server/issues/29)
- **`courtlistener_get_docket` output validation** — `document_number` is now `z.string().nullable()`, normalized via `String()`: the `/docket-entries/` endpoint serializes it as a string (`"1"`) and attachments can be non-integer (`"70-1"`). `total_entries` now guards the `/docket-entries/` URL-string count, falling back to the fetched page length. The `/search/` int form (`search_dockets`) is unaffected. [#23](https://github.com/cyanheads/courtlistener-mcp-server/issues/23)
- **`courtlistener_get_docket` `filepath_local`** — now a fully-qualified `https://storage.courtlistener.com/...` URL; CourtListener serves a relative RECAP path that 404s as-is. Already-absolute URLs pass through unchanged. [#26](https://github.com/cyanheads/courtlistener-mcp-server/issues/26)
- **`courtlistener_get_citations` citing pagination** — the cursor is now an offset into the already-computed cited-ID list, so `direction: "citing"` advances past the first page and `next_cursor` nulls when the list is exhausted (previously it re-sliced from index 0, returning page 1 forever). [#24](https://github.com/cyanheads/courtlistener-mcp-server/issues/24)
- **429 fail-fast** — all three `rateLimited(...)` sites carry `retryable: false`, so `withRetry`'s per-error opt-out skips them: a 429 now fails in one attempt instead of three futile 2/4/8s retries that can't clear CourtListener's per-minute/hour/day windows. The tool-level contract still advertises `retryable: true` to the agent, which can honor `Retry-After`. [#25](https://github.com/cyanheads/courtlistener-mcp-server/issues/25)
