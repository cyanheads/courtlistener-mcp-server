# 0.3.0 — 2026-07-10

## Changed

- **`courtlistener_get_opinion`** — adopts outline-on-overflow: when combined opinion text exceeds the inline byte budget, the response returns `kind: 'outline'` with one section per opinion variant (`opinion_<id>`) plus a `retrieval_notice`, instead of silently truncating `plain_text`/`html_text` in `content[]`. Cheap cluster metadata (case name, court, citations, syllabus) stays present in every response, outline or full. New input `sections` re-calls the tool for specific variants in full. [#31](https://github.com/cyanheads/courtlistener-mcp-server/issues/31)
- **`courtlistener_get_oral_argument`** — same pattern for the transcript field: overflow returns a section outline instead of truncating `content[]`; new input `sections` (e.g. `["transcript"]`) re-calls for the full record. [#31](https://github.com/cyanheads/courtlistener-mcp-server/issues/31)
- **Breaking** — consumers reading full opinion/transcript text from `structuredContent` must handle the `kind: 'outline'` arm and re-call with `sections` to retrieve omitted text on large payloads; small payloads that fit inline are unaffected.

## Fixed

- **`courtlistener_get_oral_argument` `panel_ids`** — the detail endpoint returns `panel` as person resource URIs (`.../people/{id}/`), not numeric IDs, so output validation failed outright on any record with a non-empty panel. Now extracts numeric IDs via URI-tail matching, mirroring the existing `docket`/`opinions_cited` extraction pattern. [#30](https://github.com/cyanheads/courtlistener-mcp-server/issues/30)
