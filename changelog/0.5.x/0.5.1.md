# 0.5.1 — 2026-07-29

## Changed

- **User-Agent** — the outbound version now reads from the running server's config (`core.config.mcpServerVersion`) via a new `CourtListenerServiceConfig`, replacing a cast to the framework's `AppConfig` that never actually carried it. [#55](https://github.com/cyanheads/courtlistener-mcp-server/issues/55)
- **Rate-limit copy** — tool descriptions, server instructions, the README, and the `legal-research` prompt attribute the 5 req/min, 50/hr, 125/day figures to CourtListener's published free tier rather than asserting them as measured, and point at the returned `Retry-After` instead.
- **`get()`/`post()`** — the unreachable non-2xx fallback branches are removed; `fetchWithTimeout` already throws on any non-2xx response before those branches could run.

## Fixed

- **`courtlistener_get_parties`** — attorney relationships are now scoped to the requested docket before attorney IDs are collected. A `/parties/` record carries a party's attorney relationships across every docket that party has ever appeared on, so a repeat litigant's counsel from unrelated cases were reported as counsel here; heavily-litigated parties also 414'd. [#45](https://github.com/cyanheads/courtlistener-mcp-server/issues/45)
- **`courtlistener_get_parties`** — attorney name and contact now resolve through `/attorneys/?docket=<id>`, cursor-walked up to 5 pages (`ATTORNEY_PAGE_LIMIT`). `/attorneys/?id=A&id=B` is not a batch filter upstream — `id` is an exact lookup and repeated params collapse to the last one — so detail previously came back empty for every attorney but one; a docket past the cap logs a warning and leaves the surplus names empty instead of failing silently. [#59](https://github.com/cyanheads/courtlistener-mcp-server/issues/59)
- **`classifyFetchError`** — the upstream `Retry-After` header is now threaded onto the rate-limit error's `data.retryAfter` instead of discarded. `retryable` flips `true → false` across every tool's rate-limit contract: a live 429 has quoted a 3232-second wait, which the framework's 2/4/8s backoff can never clear, and the service was already putting `retryable: false` on the wire while the definitions advertised `true`. [#52](https://github.com/cyanheads/courtlistener-mcp-server/issues/52)
- **`courtlistener_get_parties`** — `role_code` 1 and 2 were swapped in the description ("Attorney to be noticed" and "Lead attorney"). A decoded `role` label and the relationship's `date_action` are added alongside the raw code, and `role_code`/`AttorneyRelationship.role` are now typed and validated as nullable to match upstream, which sends no code when a PACER role text can't be mapped. [#54](https://github.com/cyanheads/courtlistener-mcp-server/issues/54)
- **`courtlistener_get_parties`** — the `totalCount` enrichment field is now optional, matching that this endpoint only returns a numeric party count on a single-page result; a multi-page list previously shipped a required field the tool couldn't populate. [#57](https://github.com/cyanheads/courtlistener-mcp-server/issues/57)
