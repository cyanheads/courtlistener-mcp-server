# 0.5.0 — 2026-07-29

## Added

- **`toStorageUrl()`** (`services/courtlistener/uri.ts`) resolves the bare relative storage paths CourtListener returns for `local_path`/`filepath_local` into fetchable `https://storage.courtlistener.com/...` URLs; applied in `courtlistener_search_oral_arguments`, `courtlistener_search_opinions`, `courtlistener_search_dockets`, and `courtlistener_get_docket`. [#53](https://github.com/cyanheads/courtlistener-mcp-server/issues/53)
- **`courtlistener_search_dockets`** results gain `case_name_full`, `attorneys`, `firms`, `referred_to`, `suit_nature`, `jurisdiction_type`; `sample_documents` gain `entry_number`, `document_type`, `page_count`, `filepath_local`. [#42](https://github.com/cyanheads/courtlistener-mcp-server/issues/42)
- **`courtlistener_search_opinions`** results carry the per-cluster `opinions[]` array (`id`, `type`, `author_id`, `per_curiam`, `download_url`, `local_path`, `cites`) — the individual opinion variants filed in the case. [#43](https://github.com/cyanheads/courtlistener-mcp-server/issues/43)
- **`courtlistener_search_judges`** `current_position` gains `job_title`, `organization_name`, `selection_method`, `date_termination`, `termination_reason`. [#44](https://github.com/cyanheads/courtlistener-mcp-server/issues/44)

## Changed

- **`courtlistener_search_dockets`** parties/attorneys/firms now read the v4 response's actual keys (`party`, `attorney`, `firm`) instead of the nonexistent `party_name`; sample-document `date_filed` now reads `entry_date_filed`. [#42](https://github.com/cyanheads/courtlistener-mcp-server/issues/42)
- **`courtlistener_search_opinions` / `courtlistener_get_citations`** `snippet` is lifted from the first `opinions[]` variant that carries one — v4 nests the matched excerpt under each cluster's opinion variants, never on the cluster row itself. [#43](https://github.com/cyanheads/courtlistener-mcp-server/issues/43)
- **`courtlistener_search_judges`** `current_position` is derived from the nested `positions[]` array (court, appointer, and dates live only there): the position with no termination date, or — when several or none qualify — the latest-starting one. [#44](https://github.com/cyanheads/courtlistener-mcp-server/issues/44)
- **`scripts/clean-mcpb.ts` / `scripts/lint-packaging.ts`** — the bundle strip step also removes platform-specific native-binding entries (`@duckdb/node-bindings-*`) alongside dependency-shipped agent docs, keeping `.mcpb` portable and under the registry size cap.
- **`scripts/check-dependency-specifiers.ts`** — now scans `overrides` under the strict no-floating-specifier rule.
- **`scripts/devcheck.ts`** — the outdated-dependency gate skips `(peer)` rows and treats any capped range (`Update === Current`, whether held by `minimumReleaseAge` or a deliberate ceiling) as non-failing.
- **`Dockerfile`** — the optional OTel dependency install runs `bun add --omit=dev --ignore-scripts`.
- **Skills** synced from the framework — `git-wrapup` 1.8 (flat-bullet tag headline, no section headers, no gates line), `field-test` 2.7, `tool-defs-analysis`, `orchestrations` 1.7.

## Removed

- **`courtlistener_search_dockets`** `document_count` — v4's `/search/` response carries no document total. [#42](https://github.com/cyanheads/courtlistener-mcp-server/issues/42)

## Fixed

- **`classifyFetchError`** reads the framework's canonical `data.status` field (was `data.statusCode`); 404 lookups (citation resolution, cluster/docket fetches) now log at `debug` via `expectedStatuses` instead of `error`, since a miss on an agent-supplied ID is a routine outcome.

## Dependencies

- `@cyanheads/mcp-ts-core` `^0.10.14` → `^0.11.0` (peer floors raised; adopts the canonical `status`/`body` error fields and `expectedStatuses` logging option added in 0.10.15).
- `@biomejs/biome` `2.5.2` → `2.5.5`, `tsc-alias` `^1.9.0` → `^1.9.1`.
