# 0.6.0 — 2026-07-30

## Changed

- **`courtlistener_lookup_courts`** — `in_use: boolean` input replaced by `status: 'active' | 'inactive' | 'any'` (default `active`). Upstream's `in_use` is a disjoint boolean filter, so `in_use: false` excluded the active bench instead of including inactive courts, and no input combination could reach the full list. `status: 'any'` omits the filter to reach every court; the default return set is unchanged. Also drops a `page_size: 500` request parameter the endpoint has always ignored — `/courts/` serves a fixed 20 rows per page regardless of what's asked for. [#49](https://github.com/cyanheads/courtlistener-mcp-server/issues/49)
- **`courtlistener_lookup_citation`** — output restructured to `{ matches: [...] }`, one entry per citation `/citation-lookup/` extracts from the submitted text. Every previous top-level field is gone: `cluster_id`, `case_name`, `court`, `date_filed`, `citations`, `normalized_citation` are replaced by `matches[].clusters[]`, which carries the same fields plus `court_id`, `docket_id`, `cite_count`, `precedential_status`, and `judges`. Each match carries its own `status` / `status_label` / `error_message` — an unresolved or ambiguous citation is now a result inside `matches`, not a `not_found` error. `court` is backfilled from each cluster's `docket_id` (previously always null, since the citation-lookup payload carries no court) — one extra request per distinct docket, capped at `COURT_BACKFILL_LIMIT` (4) per call; a response notice reports how many clusters were left unresolved past the cap. New `citation_too_long` input guard rejects passages over 64,000 characters — CourtListener's own ceiling — before spending a request. [#50](https://github.com/cyanheads/courtlistener-mcp-server/issues/50)
- **`courtlistener_get_parties`** — `page: number` input replaced by `cursor: string`; output `page` field removed, `next_cursor` now carries an opaque continuation token to pass back as `cursor`. `/parties/` is cursor-paginated upstream, so the numeric `page` was silently ignored and page 2 onward always re-served page 1. [#61](https://github.com/cyanheads/courtlistener-mcp-server/issues/61)
- **`courtlistener_get_oral_argument`** — the outline arm now carries the full record's non-transcript metadata (case name, court, docket ID, duration, panel IDs, etc.) alongside the withheld-sections list; previously it returned only `kind` and `sections`, dropping every other field to a 26-character payload. [#51](https://github.com/cyanheads/courtlistener-mcp-server/issues/51)

## Fixed

- **`citations[].volume`** on `OpinionCluster` retyped `number` → `string` — upstream's `Citation.volume` (`cl/search/models.py`) is a `TextField`, not numeric.
