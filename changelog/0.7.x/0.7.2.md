# 0.7.2 — 2026-09-20

## Added

- **Requests are paced against per-minute and per-hour windows** ([#69](https://github.com/cyanheads/courtlistener-mcp-server/issues/69)) — a process-wide queue meters every upstream call, so a short burst waits and succeeds instead of failing outright. A call that can't open a slot within its wait budget is refused before a request is spent, reported as a `rate_limited` error saying no request was sent. `COURTLISTENER_RATE_LIMIT_PER_MINUTE` (default 5) and `COURTLISTENER_RATE_LIMIT_PER_HOUR` (default 50) configure the windows for a higher token tier.
- HTTP session posture (`stateless`) is declared in `src/index.ts` via `createApp({ sessionMode })` rather than left to `MCP_SESSION_MODE` alone.

## Changed

- Both plugin manifests wire `COURTLISTENER_API_TOKEN` through to the server — Claude Code now prompts for it via `userConfig`, Codex forwards it via `env_vars`; neither previously reached the server.
- Every tool's `rate_limited` contract `when` text now covers the paced-out case alongside an upstream 429.
- `courtlistener_search_opinions` no longer advertises an `invalid_query` failure it never raised.

## Fixed

- **`rate_limited` errors carry the tool's declared recovery hint** ([#68](https://github.com/cyanheads/courtlistener-mcp-server/issues/68)) — the message and `data` previously carried only the reason and retry-after, with no `Recovery:` line for the agent to act on.

## Dependencies
