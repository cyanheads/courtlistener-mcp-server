# 0.4.2 — 2026-07-16

## Fixed

- **`courtlistener_lookup_courts` pagination** — the tool always fetched page 1 of `/courts/` with no way to reach the other ~450 of ~472 courts and no continuation signal. `CourtListenerService.listCourts()` now takes a `page` parameter; the tool gained a matching `page` input (default `1`) and `next_cursor`/`page` output fields, and `format()` renders the page and cursor on every branch, including the empty-results case. [#35](https://github.com/cyanheads/courtlistener-mcp-server/issues/35)
- **`courtlistener_search_financial_disclosures` `year` filter** — CourtListener has no server-side `year` parameter, so the filter is applied client-side to the fetched page only; the tool description and the `year` field's `.describe()` now say so, and an empty filtered page with more pages available returns a notice naming the `cursor` to check next instead of the generic no-match message. [#36](https://github.com/cyanheads/courtlistener-mcp-server/issues/36)
- **Dropped `next_cursor` on empty pages** — `courtlistener_search_financial_disclosures` and `courtlistener_get_citations` both returned early on an empty results page, before the trailing `next_cursor` render — losing the continuation from `content[]` (though not `structuredContent`) exactly when a filtered or paginated page came back empty. Both `format()` functions now render the empty-state message and the cursor unconditionally. [#36](https://github.com/cyanheads/courtlistener-mcp-server/issues/36)
