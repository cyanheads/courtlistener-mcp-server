# 0.4.1 — 2026-07-15

## Changed

- **`User-Agent` header** — `courtlistener-mcp-server/0.4.0` → `courtlistener-mcp-server/0.4.1`, synced to the package version.

## Fixed

- **`courtlistener_get_opinion` / `courtlistener_get_oral_argument` unknown `sections`** — a `sections` re-call naming no opinion variant (`get_opinion`) or no record field (`get_oral_argument`) previously returned `kind: 'full'` with only the always-kept identity fields, with no indication the request matched nothing. Both now reject unmatched names with a new `unknown_section` error: `get_opinion` lists the cluster's actual `opinion_<id>` set (or reports the cluster has none), `get_oral_argument` lists its fixed record field names. [#37](https://github.com/cyanheads/courtlistener-mcp-server/issues/37)
- **`courtlistener_get_opinion` / `courtlistener_get_oral_argument` response mode** — `format()` now renders `**Response mode:** full|outline` on every arm, including section re-calls; `kind` was already present in `structuredContent` but absent from `content[]`. [#38](https://github.com/cyanheads/courtlistener-mcp-server/issues/38)
- **Blank required query/citation strings** — `courtlistener_search_opinions`, `courtlistener_search_dockets`, `courtlistener_search_judges`, `courtlistener_search_oral_arguments` (`q`), and `courtlistener_lookup_citation` (`citation`) accepted a whitespace-only value past `.min(1)` and spent a rate-limited request on unrelated results. The fields now `.trim()`, and a new `empty_query`/`empty_citation` error rejects an empty-after-trim value before the service call. [#39](https://github.com/cyanheads/courtlistener-mcp-server/issues/39)
- **Malformed date filters** — `filed_after`/`filed_before` on `courtlistener_search_opinions`, `courtlistener_search_dockets`, and `courtlistener_get_citations`, plus `argued_after`/`argued_before` on `courtlistener_search_oral_arguments`, reached CourtListener's `/search/` endpoint and came back as an opaque `400`. New `src/services/courtlistener/dates.ts` validates real ISO 8601 calendar dates — leap-year and per-month day bounds, so `2020-13-45` and `2020-02-31` (which pass a digit-shape check) are still rejected — and a new `invalid_date` error stops the request locally before it's sent. [#40](https://github.com/cyanheads/courtlistener-mcp-server/issues/40)
